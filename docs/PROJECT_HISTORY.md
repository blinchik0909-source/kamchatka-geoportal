# История и контекст проекта (хендофф)

Этот файл — «память» проекта. Он фиксирует, что и почему было сделано, чтобы
после переезда на другой компьютер можно было продолжить работу без потери контекста.

Репозиторий: `https://github.com/blinchik0909-source/kamchatka-geoportal.git`
Ветка: `main`. Хостинг задуман под GitHub Pages / Cloudflare Pages (статика).

---

## 1. Что это за проект
Статический геопортал «Геологические достопримечательности Камчатки» на
**MapLibre GL JS** (+ **Turf.js**, **osmtogeojson**). Без бэкенда и сборщика —
набор статичных файлов.

### Стек и внешние сервисы
- **MapLibre GL JS 4.7.1** — карта.
- **Turf.js 7.1.0** — геометрия/измерения (расстояния, площади).
- **osmtogeojson 3.0.0-beta.5** — конвертация ответов Overpass в GeoJSON.
- **Overpass API** (публичный) — подгрузка OSM-слоёв по видимой области.
- **BRouter** (`https://brouter.de/brouter`, без ключа) — маршрутизация с
  геометрией, тегами дорог (surface/highway) и высотами.

### Карта файлов
```
index.html            # разметка; версии статики через ?v=NN (сейчас v=34)
css/style.css         # стили (в т.ч. панель маршрута .route-*)
js/config.js          # КОНФИГ: подложки, тематические слои, OSM-слои, поля попапа
js/app.js             # движок: карта, слои, попапы, измерения, МАРШРУТИЗАЦИЯ
data/*.geojson        # данные: dostoprimechatelnosti, volcanoes, springs, geology, soil
images/               # фото объектов (по желанию)
docs/PROJECT_HISTORY.md  # этот файл
```

## 3. Подсистема маршрутизации (главное, что делали в последних сессиях)
Весь код — в `js/app.js`, секция «Прокладка маршрутов (BRouter…)».

### Идея
Один сквозной **мультимодальный** маршрут до объекта:
1. **Авто** от старта до ближайшей проезжей точки к цели (профиль `car-fast`).
2. **Пешком** от конца авто-части до самой цели (профиль `hiking-mountain`).
3. Авто-часть делится на фазы по покрытию (теги OSM `surface`/`highway`):
   - «Хорошая дорога» (асфальт/твёрдое),
   - «Просёлок» (гравий/грунт/треки).
4. Если авто-маршрута нет → весь путь пешком; если ничего не строится → прямая («по прямой»).
5. Если пеший маршрут не строится, но остаётся разрыв ≥80 м — дотягиваем прямой пеший остаток.

### Отрисовка (слои источника `route`)
- `route-halo` — белая обводка под сегментами.
- `route-drive` — сплошная, цвет по фазе (синий «Хорошая дорога», оранжевый «Просёлок»).
- `route-foot` — зелёный пунктир (пешком).
- `route-straight` — красный пунктир (запасная прямая).
- `route-ends` — точки старта (зелёная) и цели (красная).
Свойства фич: `{ kind:"seg"|"straight", segType:"drive"|"foot", phase }`.

### Панель маршрута
DOM-панель `.route-panel` (слева сверху). Кнопка запуска — в попапе объекта
(`.pp-route-btn`, делегирование клика внизу файла). Старт можно задать:
геолокацией, кликом по карте («указать»), либо «Петропавловск-Камчатский».
Показывается раскладка по этапам (расстояние · время, для пешего — набор высоты ↑)
и «Итого».

### Расчёт времени (ВАЖНО: считаем сами, не берём время BRouter)
Модель времени BRouter заточена под велосипед → для авто нереалистична.
Средние скорости откалиброваны под Камчатку (константы в `js/app.js`):
- Панель показывает время для двух видов транспорта (`VEHICLE_SPEED`), т.к. по Камчатке
  реально перемещаются на вахтовках и вездеходах (скорости по типу покрытия, км/ч):
  - 🚛 «Вахтовка» — асфальт **60**, гравийная трасса **45**, просёлок/неизвестный **15**;
  - 🚜 «Вездеход» — асфальт **40**, гравийная трасса **30**, просёлок/неизвестный **12**.
  Панель — две строки с ПОЛНЫМ временем/расстоянием до цели (без отдельного блока «Итого» — убран по просьбе).
  Участок без дорог в OSM — ❓ «Неизвестный маршрут» (`UNKNOWN_PHASE`), показывает ДВА сценария:
  - «если проедет машина»: 🚛 15 / 🚜 12 км/ч (время также входит в общие строки транспорта);
  - «если пешком»: `footTime()` = 4 км/ч + Наисмит (`NAISMITH_SEC_PER_M=6`).
  СПЕШИВАНИЕ: кнопка «🥾 Отметить спешивание» → клик по карте привязывается к ближайшей
  вершине неизвестного участка (`setDismount`); панель показывает: до точки на транспорте,
  дальше пешком (с оставшимся набором высоты) и сумму до цели. Состояние в
  `routeState.unknownCoords/driveTimes/dismount`; оранжевая точка role=dismount на карте.
  ВЁРСТКА панели — карточки (`.route-card`): шапка (чип цвета + название + время/дистанция),
  внутри — строки «показатель → значение» (`.route-kv`, flex space-between).

### Стратегия построения (багфикс «кривых» маршрутов)
Раньше при неудаче авто-маршрута весь путь строился пешим профилем — BRouter уводил
трек по тропам на сотни км (напр. Голыгинские источники: 782 км «пешком» на север).
Теперь (`computeRoute`/`carApproach`/`finishWithCar`/`footSane`):
1. авто-плечо через `driveTo`: сначала профиль car-fast, при отказе — trekking
   (те же дороги, но разрешены ПАРОМЫ и любые покрытия; именно паром через
   р. Камчатка ломал car-fast на дороге Козыревск→Ключи; время считаем сами по тегам);
   если цель не привязалась — `roadApproach`: каскад радиусов 15→40 км поиска
   ближайшей вершины дороги/просёлка через Overpass (`nearestRoadPoint`) и
   `driveTo` туда — даже далёкий просёлок лучше прямой через тайгу;
   последний резерв — перебор точек на прямой (`carApproach`, доли 0.9/0.7/0.45);
   ВСЕ авто-плечи проходят через `trimDriveLeg` (v=34): плечо обрезается на
   первом непроезжем месте — тропа в тегах (highway=path/footway/steps/…,
   NON_DRIVABLE_RE) либо устойчивый уклон вдоль пути > DRIVE_MAX_TAN=0.25 (~14°)
   в окне DRIVE_SLOPE_WIN=300 м по 3D-координатам BRouter — «машина в вулкан
   не лезет» (баг: синее авто-плечо забиралось на кромку кратера); messages
   режутся той же дистанцией, чтобы статистика фаз совпадала с геометрией;
   остаток достраивается пешим финалом/внедорожным треком как обычно;
2. финал от конца авто-плеча — пешим профилем, НО с проверкой `footSane`
   (не длиннее прямой х3 + 3 км; НЕ ужесточать до х2 — отбраковывало хорошие
   извилистые пролесные дороги; от огромных петель защищает trekking-фолбэк авто-плеча);
3. целиком пеший маршрут допускается только до 30 км по прямой;
4. ПРЯМЫЕ ЛИНИИ НЕ РИСУЮТСЯ ВООБЩЕ (по просьбе: идти по прямой через тайгу —
   безумие): если финал не построился — серый маркер role=route-end «конец
   вычисляемого маршрута» + блок `.route-cutoff` в панели (`result.cutoff` = остаток
   метров по прямой); `straightFallback` тоже без линии — только маркеры и сообщение
   «маршрут вычислить не удалось».
  На карте ВСЕ дорожные сегменты — ОДНИМ цветом (`ROAD_COLOR` #1a73e8, цвета по
  покрытию убраны по просьбе — «по крайней мере пока»); «неизвестный» участок —
  зелёный пунктир. Классификация фаз СОХРАНЕНА — нужна для расчёта времени (VEHICLE_SPEED).
- Классификация (`surfaceFromTags`): твёрдое покрытие → «Хорошая дорога»;
  мягкое покрытие на `highway=motorway..tertiary` → «Гравийная трасса» (`grade`);
  остальное мягкое/track → «Просёлок».
- Набор высоты берётся из 3D-геометрии BRouter (`computeAscent`) и показывается справочно.

### ВНЕДОРОЖНЫЙ ТРЕК (отдельная экспериментальная функция, v=33)
Когда маршрут упёрся в «конец вычисляемого маршрута», в панели появляется кнопка
«🚜 Проложить внедорожный трек» (`runOffroad`). Алгоритм (`computeOffroadTrack`):
1. Сетка высот: DEM-тайлы Terrarium (AWS elevation-tiles-prod, без ключа, CORS открыт),
   z=11→8 чтобы ≤12 тайлов, даунсемпл до ≤400 ячеек по стороне (ячейка ~40–90 м);
   декод через canvas: elev = R*256+G+B/256−32768.
2. Препятствия из OSM (Overpass, bbox): natural=water|wetland (полигоны) и natural=cliff
   (линии) растеризуются на canvas размером с сетку → маска blocked (быстро, без
   point-in-polygon); вокруг старта/цели маска снимается (unblockAround).
3. A* по 8-связной сетке (OffHeap — бинарная куча): стоимость = дистанция ×
   (1+3·(tan/лимит)²); склон круче лимита — непроходим. Трек строится по лимиту
   вездехода; OFFROAD_TAN_LIMIT: вахтовка 15°, вездеход 25°.
4. По треку: дистанция/набор/макс. уклон; время по каждому транспорту (база —
   скорость UNKNOWN_PHASE, на предельном уклоне остаётся 35%); если уклон выше
   лимита вахтовки — «не пройдёт (уклон)»; пеший вариант — footTime.
5. Отрисовка: фиолетовый пунктир (слой route-offroad, kind=offroad, OFFROAD_COLOR
   #8e44ad), геометрия упрощается turf.simplify; карточка в панели + кнопка «Убрать».
   Лимит OFFROAD_MAX_STRAIGHT = 40 км по прямой. Состояние:
   `routeState.offroad/offroadError/cutoffPoint` (сбрасываются в computeRoute/clearRoute).

Ориентиры из отчётов туристов (сентябрь 2026, перепроверка по форумам/блогам):
- ПКЦ→Козыревск: 470–500 км (300 асфальт + 170 гравий) — 7–9 ч (модель: ~8.4 ч ✓);
- Козыревск→стоянка «Клешня» (Толбачик): 70 км лесной дороги с бродами — 3–5 ч (модель: ~4.7 ч ✓);
- развилка Мутновский/Горелый → Мутновский: ~2 ч по буеракам/снежникам;
- восхождение на Плоский Толбачик от «Клешни»: 12 км, набор 1680 м — 5–6 ч
  (модель: 3 ч + 2.8 ч Наисмит = 5.8 ч ✓, пешая часть не менялась);
- Мутновский пешком: 8.5 км, набор ~530 м — ок. 3 ч (модель совпадает ✓).

### Ключевые функции (js/app.js)
- `setupRouting()` — источники/слои/панель/клик «указать старт».
- `startRouteTo(lng,lat,name)` — запуск из попапа.
- `brouter(a,b,mode)` — запрос одного «плеча» → `{coords, messages, ...}` | null.
- `computeRoute()` — оркестрация авто→пешком (с `routeReq` для игнора устаревших ответов).
- `assemble()` — сборка фич, статистики по фазам, набор высоты, отрисовка, fitBounds.
- `buildLeg()` / `parseSegs()` — разбивка геометрии по фазам + статистика.
- `surfaceFromTags()` — классификация покрытия из тегов (`hard`/`grade`/`soft`).
- `vehicleTime()` / `computeAscent()` — время по транспорту/покрытию + набор высоты.
- `straightFallback()` — прямая, если маршрут не найден.
- `renderRoutePanel()` — рендер панели/раскладки.

### Оговорки / зоны риска
- Точность фаз и наличие пешего этапа зависят от полноты OSM на Камчатке.
- BRouter — публичный сервер сообщества, без гарантий аптайма; при желании — свой инстанс.
- Скорости/Наисмит — эвристика; при необходимости менять в `VEHICLE_SPEED`/`NAISMITH_SEC_PER_M`.

## 4. Соглашения по данным и конфигу
- Тематические слои и поля попапа настраиваются в `js/config.js` (см. README).
- Поля объекта: `name`, `type`, `description`, `photo` + произвольные атрибуты.
- Достопримечательности обогащены геологией (Подразделение/Описание/Индекс) через
  пространственное соединение с `geology.geojson`.
- OSM-слои (вкладка «Карт. основа») грузятся по видимой области с индивидуальным `minZoom`.
- При изменении статики поднимать `?v=NN` в `index.html` (сейчас **v=34**), чтобы сбросить кэш.

## 5. Как продолжить на новом компьютере
1. Установить Git; склонировать репозиторий:
   ```bash
   git clone https://github.com/blinchik0909-source/kamchatka-geoportal.git
   ```
2. Локальный просмотр (нужен сервер из-за fetch):
   ```bash
   python -m http.server 8000   # затем http://localhost:8000
   ```
3. Открыть папку в IDE с Cascade и дать этот файл (`docs/PROJECT_HISTORY.md`) как контекст —
   в нём зафиксированы все решения. Дословную переписку перенести нельзя, но здесь есть
   всё необходимое, чтобы восстановить контекст и продолжить.
4. Если Cascade используется под тем же аккаунтом — сохранённые «памяти» подтянутся автоматически.
